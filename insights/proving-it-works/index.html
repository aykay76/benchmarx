Agentic engineering

Proving it works.

A demo shows an agent working once. Production needs evidence that it works reliably, and an early warning for when it stops.

5 min read

Why agents are harder to test

Ordinary software gives the same output for the same input. Agents don't. They're non-deterministic, they work in several steps, and the quality of the result depends on the route taken as well as the destination.

Changing a prompt, a tool, a data source or the model itself changes behaviour everywhere at once. Without a way to measure that, every change is a guess.

A test pyramid for agents

Lean on cheap, deterministic checks as far as possible, and save the expensive, judgement-based ones for what they alone can catch.

What to measure

Outcome

Did it complete the task, correctly and completely?

Behaviour

Did it use the right tools in a sensible order, and stay inside its limits?

Cost and speed

What does a successful task cost, and how long does it take?

Safety

Does it resist injected instructions and respect the boundaries it was given?

If you can't see it, you can't fix it

Every model call, tool call, state change and approval should be traced under a single run identifier, so a bad outcome can be replayed and explained. Alongside that you want spend broken down by workflow and customer, limits on rates, and a kill switch that someone actually knows how to use.

When something goes wrong, you need to answer one question quickly: was it the model, the context or the tool? Without traces, you're guessing.

Where this gets hard

What surprises teams after the demo

It also broke twelve others, and nobody noticed for a week. You need a regression set that runs on every change, including model upgrades, which are changes too.

Using a model to grade a model is useful and also biased. Judges need calibrating against human-labelled examples, and deterministic checks should go first wherever they can.

A cheaper model that needs three retries and a human fix can cost more than a stronger one that gets it right. Optimise the cost of getting a task done, not the price of a token.

Providers update models, sources change and users find new ways to ask. Quality drifts unless something is measuring it continuously and someone owns the result.
